Plan

Status: untested DIY design. The board and case are designed and pass automatic design-rule checks; nothing has been built, and firmware is not written. Sections marked planned are intent, not results.

Vision

Control several computers from one without cables, a KVM or software on the targets. A tiny USB stick goes into each target and appears as an ordinary keyboard, mouse, drive, serial port or network card. One more stick goes into your own computer. They find each other by radio, so you pick a target in a web page and drive it.

Architecture

Both sticks are the same hardware. Firmware decides the role: host shows up on your computer as a control device and fans commands out to paired sticks; target receives commands and presents the matching USB device to the machine it is plugged into. Use the Signal tab in the explorer to trace each path.

Hardware

  • Module: ESP32-S3-MINI-1-N4, pre-certified, native full-speed USB device, ESP-NOW, Wi-Fi 4, BLE 5.
  • Power: AP2112K-3.3 from the port's 5 V; 600 mA budget against about 150 mA average.
  • Board: 33 × 17.4 mm, 4 layers (signal, GND, 3V3, GND), 1.6 mm. Antenna end is a keep-out on all layers.
  • Connector: Würth 692112030100 USB-A plug, hand-soldered.
  • Case: two PETG halves, snap-fit lid, 3 perimeters, 0.2 mm layers, no supports.
  • Known gaps: no ESD diode on USB lines; LED runs at 3.3 V and may be dim; no schematic or ERC (nets live in build_board.py).

Pairing

  1. Plug a blank stick into the computer once; the host stick hands it the fleet key.
  2. Plug it into any target; it joins within a second or two.
  3. Up to about 20 targets per host; run two hosts for more.
  4. Firmware updates go out over the radio.

Security

A target stick that obeys the air is a remote keyboard, so pairing is the whole security model.

  • Frames are encrypted and authenticated with the fleet key; unpaired senders are dropped.
  • Provisioning only happens over USB, never over the air.
  • Replay protection with a monotonic counter per sender.
  • Lost sticks: re-key the fleet from the host, which invalidates every stick that missed the rotation.
  • Firmware images must be signed before OTA is accepted.
Planned, not implemented. A threat model review is a gate before any public firmware release.

Roadmap

  1. Phase 0 · Idea (done)
    What it does, derived case dimensions, 3D explorer.
  2. Phase 1 · Board and case design (done)
    KiCad board generated by script, DRC clean, Gerbers, BOM, placement, printable STL. Open gate: fab preview accepts the files.
  3. Phase 2 · First article
    Order minimum quantity, fill LCSC part numbers, check rotation offsets. Assemble, hand-solder plug. Gate: stick enumerates on USB and powers the module.
  4. Phase 3 · Bring-up firmware
    Flash via BOOT/GND short, LED, USB HID keyboard, ESP-NOW ping between two sticks. Gate: keystroke crosses the radio.
  5. Phase 4 · Fleet
    Pairing, encryption, multiple targets, host web page over WebUSB. Gate: five sticks, measured latency and range.
  6. Phase 5 · Hardening
    ESD diode and board respin, LED supply fix, OTA with signing, EMC pre-scan. Gate: threat-model review passed.
  7. Phase 6 · Share
    Write up what worked, tag a release of the files and firmware.
